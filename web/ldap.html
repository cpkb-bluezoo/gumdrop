Gumdrop LDAP Client & Realm

← Back to Main Page

Gumdrop provides a fully asynchronous LDAPv3 client and a companion LdapRealm that integrates LDAP-based authentication and authorisation into the framework's centralised realm interface. Both are built on gumdrop's non-blocking I/O architecture and use BER encoding (ITU-T X.690) for wire-level communication.

Architecture

The LDAP client follows the same asynchronous, callback-driven patterns as other Gumdrop clients (Redis, SMTP, HTTP). The connection progresses through a series of typed interfaces that enforce the correct protocol sequence.

Key Components

The client types live in org.bluezoo.gumdrop.ldap.client.

  • LdapClient — connection factory; configures transport, TLS, and initiates the connection
  • LdapClientProtocolHandler — protocol handler implementing BER message encoding/decoding and the three state interfaces
  • LdapConnected — interface available immediately after connection; offers bind(), bindAnonymous(), bindSASL(), startTLS(), and unbind()
  • LdapPostTLS — interface available after STARTTLS; same bind operations, no second STARTTLS
  • LdapSession — interface available after a successful bind; provides search, modify, add, delete, compare, modifyDN, extended, rebind, rebindSASL, abandon, setRequestControls()/getResponseControls(), and unbind
  • LdapConnectionReady — entry-point callback receiving the initial LdapConnected
  • BerEncoder/BerDecoder (package org.bluezoo.gumdrop.asn1, shared rather than LDAP-specific) — BER encoding for all wire-level messages

Client Usage

Create an LdapClient, configure it, then call connect() with a handler:

In the client examples on this page, gumdrop is the Gumdrop instance returned by Gumdrop.boot(); a client is given it when it connects. 

LdapClient client = new LdapClient(selectorLoop, "ldap.example.com", 389);

client.connect(gumdrop, new LdapConnectionReady() {
    @Override
    public void handleReady(LdapConnected connection) {
        connection.bind("cn=admin,dc=example,dc=com", "secret",
            new BindResultHandler() {
                @Override
                public void handleBindSuccess(LdapSession session) {
                    // Authenticated — perform directory operations
                }

                @Override
                public void handleBindFailure(LdapResult result,
                                              LdapConnected conn) {
                    System.err.println("Bind failed: "
                        + result.getDiagnosticMessage());
                    conn.unbind();
                }
            });
    }

    @Override
    public void onConnected(Endpoint endpoint) {
        // TCP connection established
    }

    @Override
    public void onSecurityEstablished(SecurityInfo info) {
        // TLS handshake complete
    }

    @Override
    public void onError(Exception cause) {
        cause.printStackTrace();
    }

    @Override
    public void onDisconnected() {
        // Connection closed
    }
});

Connection Modes

ModeDefault PortDescription
Plaintext LDAP 389 Standard LDAPv3 (RFC 4511). Optionally upgrade to TLS via STARTTLS.
LDAPS (implicit TLS) 636 TLS established before any LDAP traffic (RFC 4513 §3.1.3). Set client.secure(true) and pass port 636 explicitly: the default port is always 389.

Binding (Authentication)

Simple Bind (RFC 4513 §5.1)

Simple bind sends a distinguished name and password in the clear (or over TLS). This is the most common authentication method: 

connection.bind("cn=admin,dc=example,dc=com", "secret", bindHandler);

Anonymous Bind

connection.bindAnonymous(bindHandler);

SASL Bind (RFC 4513 §5.2)

SASL bind uses a challenge-response mechanism to authenticate without sending the password in the clear. Gumdrop implements client-side SASL using its own cryptographic primitives (SaslUtils), so all mechanism evaluation is non-blocking and safe for the NIO event loop.

Supported SASL Mechanisms

MechanismRFCDescription
PLAIN RFC 4616 Single-step: sends \0authcid\0password. Requires TLS.
EXTERNAL RFC 4422 App. A Relies on TLS client certificate. No credentials transmitted.
GSSAPI RFC 4752 Kerberos V5 authentication. Requires a JAAS Subject with valid credentials: create it with SaslUtils.createClient("GSSAPI", user, null, host, subject) (it returns null without a Subject and host). The first evaluateChallenge() call may contact the KDC and block. The overload bindSASL(mechanism, handler, ExecutorService) offloads it to a worker thread, but it is only on the concrete LdapClientProtocolHandler (cast the LdapConnected handle); the interface bindSASL() and rebindSASL() do not offload.

SaslUtils.createClient() also supports OAUTHBEARER and XOAUTH2, which are not normally used with LDAP. It returns null for a mechanism it cannot create, so check the result.

Usage

import org.bluezoo.gumdrop.auth.SaslClientMechanism;
import org.bluezoo.gumdrop.auth.SaslUtils;

SaslClientMechanism mechanism =
    SaslUtils.createClient("PLAIN", "admin", "secret",
                           "ldap.example.com");
if (mechanism == null) {
    // mechanism not available
}

connection.bindSASL(mechanism, new BindResultHandler() {
    @Override
    public void handleBindSuccess(LdapSession session) {
        // Authenticated via PLAIN (over TLS)
    }

    @Override
    public void handleBindFailure(LdapResult result,
                                  LdapConnected conn) {
        System.err.println("SASL bind failed: "
            + result.getDiagnosticMessage());
        conn.unbind();
    }
});

The protocol handler manages intermediate SASL_BIND_IN_PROGRESS (result code 14) responses internally and only invokes the callback on final success or failure.

Search Operations

After binding, the LdapSession interface provides search with the full RFC 4511 §4.5 syntax: 

SearchRequest search = new SearchRequest();
search.setBaseDN("dc=example,dc=com");
search.setScope(SearchScope.SUBTREE);
search.setFilter("(&(objectClass=person)(uid=alice))");
search.setAttributes("cn", "mail", "memberOf");
search.setSizeLimit(10);

session.search(search, new SearchResultHandler() {
    @Override
    public void handleEntry(SearchResultEntry entry) {
        System.out.println("DN: " + entry.getDN());
        for (String mail : entry.getAttributeStringValues("mail")) {
            System.out.println("  mail: " + mail);
        }
    }

    @Override
    public void handleReference(String[] referralUrls) {
        // Continuation references (RFC 4511 §4.5.3)
    }

    @Override
    public void handleDone(LdapResult result, LdapSession session) {
        if (!result.isSuccess()) {
            System.err.println("Search failed: "
                + result.getDiagnosticMessage());
        }
        session.unbind();
    }
});

Search Scope

ScopeDescription
SearchScope.BASESearch only the base entry
SearchScope.ONESearch immediate children of the base
SearchScope.SUBTREESearch the entire subtree rooted at the base

Search Filters (RFC 4515)

Filters use the standard LDAP string representation. The encoder supports equality (=), presence (=*), substring (*), greater-or-equal (>=), less-or-equal (<=), approximate match (~=, RFC 4515 §4 / context tag 8), extensible match (:=, RFC 4515 §4 / context tag 9), AND (&), OR (|), and NOT (!). Extensible match uses the syntax [attr][:dn][:matchingRule]:=value.

Directory Modification Operations

The LdapSession interface provides full CRUD operations against the directory:

MethodRFC 4511Description
modify(dn, modifications, handler) §4.6Modify attributes of an existing entry
add(dn, attributes, handler) §4.7Add a new entry
delete(dn, handler) §4.8Delete an entry
modifyDN(dn, newRDN, deleteOldRDN, handler) §4.9Rename or move an entry
compare(dn, attribute, value, handler) §4.10Compare an attribute value
extended(oid, value, handler) §4.12Extended operation (e.g. password modify, whoami)
rebind(dn, password, handler) §4.2Re-bind with different credentials
rebindSASL(mechanism, handler) §4.2Re-bind with a different SASL mechanism
abandon(messageId) §4.11Cancel an in-progress operation

Abandon

The abandon(int messageId) method sends an AbandonRequest (RFC 4511 §4.11) to cancel an in-progress operation, such as a long-running search. The server is not required to honour the request and does not send a response. Any pending callback for the abandoned operation is removed immediately on the client side.

Controls

LDAP Controls (RFC 4511 §4.1.11) extend the behaviour of operations. The Control class represents a control with an OID, criticality flag, and optional value.

Request Controls

Call setRequestControls(List<Control>) before an operation to attach controls. They are consumed (cleared) once the next request is sent: 

import org.bluezoo.gumdrop.ldap.client.Control;
import java.util.Collections;

// Paged results control (RFC 2696); encodePagedResultsControl is your own
// BER-encoding helper, not part of the API
byte[] pagedValue = encodePagedResultsControl(100, cookie);
Control paged = new Control(Control.OID_PAGED_RESULTS, true, pagedValue);
session.setRequestControls(Collections.singletonList(paged));
session.search(request, searchHandler);

Response Controls

After receiving a response, call getResponseControls() on the session to retrieve any controls the server included. Controls are also available on LdapResult.getControls().

Unsolicited Notifications & Intermediate Responses

Unsolicited Notifications (RFC 4511 §4.4) are server-initiated messages with messageID 0. The client automatically handles the Notice of Disconnection (OID 1.3.6.1.4.1.1466.20036) by logging the diagnostic message, notifying the handler via onError(), and closing the connection.

IntermediateResponse (RFC 4511 §4.13) messages are delivered to the pending callback for the corresponding operation, provided it implements IntermediateResponseHandler. This enables multi-stage extended operations to return incremental data.

STARTTLS

Upgrade a plaintext connection to TLS using the STARTTLS extended operation (RFC 4511 §4.14, RFC 4513 §3). The client must have TLS credentials configured before connecting: 

LdapClient client = new LdapClient(selectorLoop, "ldap.example.com", 389);
client.tls(TlsConfig.keystore(Path.of("/path/to/truststore.p12"), "changeit"));

client.connect(gumdrop, new LdapConnectionReady() {
    @Override
    public void handleReady(LdapConnected connection) {
        connection.startTLS(new StartTLSResultHandler() {
            @Override
            public void handleTLSEstablished(LdapPostTLS secureConn) {
                // Now bind over TLS
                secureConn.bind("cn=admin,dc=example,dc=com",
                                "secret", bindHandler);
            }

            @Override
            public void handleStartTLSFailure(LdapResult result,
                                              LdapConnected conn) {
                System.err.println("STARTTLS failed: "
                    + result.getDiagnosticMessage());
                conn.unbind();
            }
        });
    }
    // ... lifecycle callbacks
});

TLS / LDAPS

For implicit TLS (LDAPS on port 636), enable secure mode before connecting: 

LdapClient client = new LdapClient(selectorLoop, "ldap.example.com", 636);
client.secure(true)
      .tls(TlsConfig.keystore(Path.of("/path/to/truststore.p12"), "changeit"));
client.connect(gumdrop, handler);

Client Configuration Options

LdapClient is configured with fluent methods named for the setting, each returning the client (for example new LdapClient().host("ldap.example.com").port(636).secure(true)). All TLS settings other than whether to use TLS at all are carried by a TlsConfig.

MethodDescription
secure(boolean) Enable implicit TLS (LDAPS); does not change the default port
tls(TlsConfig) Trust material (a truststore, a PEM CA bundle or a custom X509TrustManager), a client certificate, and other TLS settings. The configuration is copied.

LdapRealm

org.bluezoo.gumdrop.auth.ldap.LdapRealm implements the framework's Realm interface, enabling LDAP-backed authentication and authorisation for the Gumdrop protocols that take a realm (SMTP, IMAP, POP3, FTP, HTTP and WebDAV, and others). It lives in the gumdrop-ldap module. Like the rest of Gumdrop's composition wiring it is configured with fluent methods named for the setting, each returning the realm.

Authentication Flow

  1. Bind to the LDAP server using a service account (bindDN/bindPassword), or anonymously if no service account is configured
  2. Search for the user under baseDN (subtree scope) with userFilter (e.g. (uid={0})), substituting the username. The username is escaped as an RFC 4515 filter value first.
  3. Re-bind as the discovered user DN with the user's password
  4. If the re-bind succeeds, the user is authenticated

Each realm operation opens its own connection, performs the whole exchange on it (service bind, search, and for a password check the re-bind as the user), and closes it. Nothing waits: the realm implements the asynchronous Realm contract, so every lookup takes a RealmCallback that is completed exactly once on the loop the realm is bound to. The protocol servers do this for you, holding the connection's next step (or the HTTP request) until the answer arrives. A timeout timer runs with each operation; a directory that is unreachable, refuses the service bind or is too slow fails the call (RealmCallback.failed), and every caller treats that as failing closed: authentication fails and the user holds no role. A wrong password or an unknown user is not a failure; it completes with false.

Outside a protocol server, call the realm the same way: 

Realm bound = realm.forSelectorLoop(loop);
bound.passwordMatch("alice", "secret", new RealmCallback<Boolean>() {
    public void completed(Boolean matched) {
        // on the loop; matched is TRUE only for a correct password
    }
    public void failed(Throwable cause) {
        // directory unreachable or too slow: treat as not authenticated
    }
});

Configuration Example

LdapRealm realm = new LdapRealm()
    .host("ldap.example.com")
    .port(389)
    .baseDN("dc=example,dc=com")
    .bindDN("cn=service,dc=example,dc=com")
    .bindPassword("secret")
    .userFilter("(uid={0})")
    .roleAttribute("memberOf")
    .timeout(30);

SASL Bind Configuration

To use SASL instead of simple bind for all LDAP operations (both service account and user authentication), set saslMechanism. The mechanism is created with SaslUtils.createClient(), so any mechanism it supports can be named; if it cannot create the mechanism the bind fails with authMethodNotSupported: 

LdapRealm realm = new LdapRealm()
    .host("ldap.example.com")
    .port(389)
    .saslMechanism("PLAIN")
    .baseDN("dc=example,dc=com")
    .bindDN("cn=service,dc=example,dc=com")
    .bindPassword("secret")
    .userFilter("(uid={0})");

LdapRealm Configuration Reference

MethodTypeDefaultDescription
host String localhost LDAP server hostname or IP address
port int 389 LDAP server port (636 for LDAPS)
secure boolean false Enable implicit TLS (LDAPS)
startTLS boolean false Upgrade each connection to TLS with STARTTLS before any bind (use with port 389). It has no effect with secure(true), which is already encrypted. If the upgrade fails the operation fails without sending any credentials.
tls TlsConfig — TLS settings for the realm's LDAP connections: trust material for verifying the server (for example TlsConfig.keystore(...) with a truststore) and a client identity if the server wants one. The configuration is copied.
baseDN String "" Base DN for user searches (e.g. dc=example,dc=com)
bindDN String — Service account DN for searching. If null or empty, anonymous bind is used.
bindPassword String — Service account password
userFilter String (uid={0}) LDAP search filter template. {0} is replaced with the escaped username. Use (sAMAccountName={0}) for Active Directory.
roleAttribute String memberOf Attribute containing group/role membership
rolePrefix String "" Prefix prepended to the role name before matching. A user is in a role if any value of roleAttribute contains the prefix followed by the role name, ignoring case (for example cn= + admins matches cn=admins,ou=groups,dc=example,dc=com).
timeout int 30 Seconds before an outstanding realm operation fails (fail closed)
saslMechanism String — SASL mechanism for LDAP binds (any mechanism SaslUtils.createClient() supports, for example PLAIN, EXTERNAL, GSSAPI). CRAM-MD5 and DIGEST-MD5 are not supported and throw IllegalArgumentException at configuration time. When null, simple bind is used.
certLookupMode LdapRealm.CertLookupMode — Certificate authentication mode: BINARY (match by DER) or SUBJECT (extract RDNs from the Subject DN). When unset, certificate authentication is not offered.
certUsernameAttribute String uid LDAP attribute to read as the username from a matched certificate entry
certSubjectFilter String — Filter template for subject-mode certificate lookup. Placeholders like {CN}, {O}, {OU} are replaced with the corresponding (escaped) RDN values from the certificate's Subject DN. Example: (uid={CN})
selectorLoop SelectorLoop — The loop the realm's LDAP connections run on. Protocol servers supply this per connection through forSelectorLoop(); set it yourself only when using the realm outside a protocol server.

Separately from the LDAP bind mechanism above, the realm offers the SASL mechanisms PLAIN, LOGIN and EXTERNAL to the protocol servers that use it, since it needs the plaintext password to perform the LDAP bind. It cannot supply a digest password hash, so the SCRAM family is not available through it.

Certificate Authentication

When certLookupMode is configured, the realm can authenticate users by their TLS client certificate. This is used by protocol handlers that support the SASL EXTERNAL mechanism (SMTP, IMAP, POP3) and by the HTTP mTLS authentication provider.

Binary Mode

Searches LDAP for a person entry whose userCertificate;binary attribute matches the DER encoding of the presented certificate: 

realm.certLookupMode(LdapRealm.CertLookupMode.BINARY)
     .certUsernameAttribute("uid");

Subject DN Mode

Extracts RDN components from the certificate's Subject DN and substitutes them into a filter template. Without a certSubjectFilter the lookup fails: 

realm.certLookupMode(LdapRealm.CertLookupMode.SUBJECT)
     .certSubjectFilter("(uid={CN})")
     .certUsernameAttribute("uid");

SelectorLoop Affinity

When using the LDAP client from within a Gumdrop server handler, create the client on the same SelectorLoop as the originating connection. This ensures that all callbacks execute on the same thread, avoiding synchronisation overhead: 

SelectorLoop loop = endpoint.getSelectorLoop();
LdapClient ldap = new LdapClient(loop, "ldap.example.com", 389);

The LdapRealm handles SelectorLoop affinity via its forSelectorLoop() method, which the protocol handlers (SMTP, IMAP, POP3, FTP, MQTT, SOCKS, HTTP and WebDAV) call for each connection to obtain a copy of the realm whose LDAP connections, timers and callbacks run on that connection's loop.

Integration Examples

Using LdapRealm with SMTP

LdapRealm realm = new LdapRealm()
    .host("ldap.example.com")
    .port(636)
    .secure(true)
    .tls(TlsConfig.keystore(Path.of("/etc/gumdrop/truststore.p12"), "changeit"))
    .baseDN("dc=example,dc=com")
    .bindDN("cn=smtp-service,dc=example,dc=com")
    .bindPassword("secret")
    .userFilter("(mail={0})");

TlsConfig tls = TlsConfig.keystore(Path.of("/etc/gumdrop/keystore.p12"), "changeit");
SmtpServer smtp = SmtpServer.compose()
    .listener(new SmtpListener().port(587).secure(true).tls(tls))
    .realm(realm)
    .sessionProvider(SmtpServerSessionProviders.relay()
        .hostname("mail.example.com"))
    .server();

Active Directory Configuration

LdapRealm realm = new LdapRealm()
    .host("dc01.corp.example.com")
    .port(636)
    .secure(true)
    .tls(TlsConfig.keystore(Path.of("/etc/gumdrop/ad-truststore.p12"), "changeit"))
    .baseDN("dc=corp,dc=example,dc=com")
    .bindDN("cn=svc-gumdrop,ou=Service Accounts,dc=corp,dc=example,dc=com")
    .bindPassword("secret")
    .userFilter("(sAMAccountName={0})")
    .roleAttribute("memberOf")
    .rolePrefix("cn=");

Programmatic LDAP Client Usage

Binding and then adding a directory entry with the client directly (UTF_8 is java.nio.charset.StandardCharsets.UTF_8, statically imported): 

LdapClient client = new LdapClient(selectorLoop, "ldap.example.com", 389);

client.connect(gumdrop, new LdapConnectionReady() {
    @Override
    public void handleReady(LdapConnected connection) {
        connection.bind("cn=admin,dc=example,dc=com", "secret",
            new BindResultHandler() {
                @Override
                public void handleBindSuccess(LdapSession session) {
                    // Add a new entry
                    Map<String, List<byte[]>> attrs = new HashMap<>();
                    attrs.put("objectClass", List.of(
                        "inetOrgPerson".getBytes(UTF_8),
                        "top".getBytes(UTF_8)));
                    attrs.put("cn", List.of("Alice".getBytes(UTF_8)));
                    attrs.put("sn", List.of("Smith".getBytes(UTF_8)));
                    attrs.put("mail", List.of(
                        "alice@example.com".getBytes(UTF_8)));

                    session.add(
                        "cn=Alice,ou=People,dc=example,dc=com",
                        attrs,
                        new AddResultHandler() {
                            @Override
                            public void handleAddResult(
                                    LdapResult result,
                                    LdapSession s) {
                                if (result.isSuccess()) {
                                    System.out.println("Entry added");
                                } else {
                                    System.err.println("Add failed: "
                                        + result.getDiagnosticMessage());
                                }
                                s.unbind();
                            }
                        });
                }

                @Override
                public void handleBindFailure(LdapResult result,
                                              LdapConnected conn) {
                    conn.unbind();
                }
            });
    }

    @Override
    public void onConnected(Endpoint endpoint) { }

    @Override
    public void onSecurityEstablished(SecurityInfo info) { }

    @Override
    public void onError(Exception cause) {
        cause.printStackTrace();
    }

    @Override
    public void onDisconnected() { }
});
