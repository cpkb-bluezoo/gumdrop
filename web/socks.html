Gumdrop SOCKS Proxy Server & Client

← Back to Main Page

Gumdrop provides a SOCKS proxy server and a composable SOCKS client for tunneling other protocol handlers through a proxy. The server supports SOCKS4, SOCKS4a, and SOCKS5 (RFC 1928), including username/password authentication (RFC 1929) and GSS-API authentication (RFC 1961). CONNECT, BIND, and UDP ASSOCIATE are implemented with asynchronous relaying consistent with the rest of the framework.

Architecture

A SocksServer, built with SocksServer.compose(), owns one or more SocksListener instances. Each accepted connection is handled by SocksProtocolHandler, which negotiates the SOCKS version, performs optional authentication, and establishes relays via SocksRelay, SocksBindRelay, or SocksUdpRelay as appropriate. A composed SocksServerSessionProvider supplies a SocksSessionHandler (combined ConnectHandler + BindHandler) per connection for application-level authorization.

  • org.bluezoo.gumdrop.socks.server.SocksServer — listeners, configuration, and compose(); destination filtering, relay limits, idle timeout; do not subclass for application logic
  • org.bluezoo.gumdrop.socks.server.SocksServerSessionProvider — mints a SocksSessionHandler per connection; with no provider, compose() is a ready-to-use open proxy (accept CONNECT/BIND that pass filtering; optional realm for SOCKS5)
  • org.bluezoo.gumdrop.socks.SocksListener — TCP listener; defaults to port 1080 (plaintext) or 1081 (TLS)
  • org.bluezoo.gumdrop.socks.client.SocksClientHandler — wraps another ProtocolHandler and tunnels it through a SOCKS proxy
  • org.bluezoo.gumdrop.socks.client.SocksClientConfig — version preference, credentials, handshake timeout

Configuration

Minimal proxy (no authentication)

SocksServer server = SocksServer.compose()
        .listener(new SocksListener().port(1080).bindWildcard())
        .server();
gumdrop.addServer(server);

With realm (SOCKS5 username/password)

Realm socksRealm = new BasicRealm();
// ... realm configuration ...

SocksServer server = SocksServer.compose()
        .realm(socksRealm)
        .listener(new SocksListener().port(1080).bindWildcard())
        .server();

When a realm is set on the server, it is applied to each SocksListener that does not already define its own realm. SOCKS5 clients must complete RFC 1929 username/password authentication. SOCKS4 carries an unauthenticated userid field in the request only.

TLS (sockss)

TlsConfig tls = TlsConfig.keystore(Path.of("keystore.p12"), "secret");

SocksServer server = SocksServer.compose()
        .listener(new SocksListener().port(1081).bindWildcard()
                .secure(true).tls(tls))
        .server();

If no port is set, the listener uses 1080 for cleartext and 1081 when secure(true).

Destination filtering and relay limits

SocksServer server = SocksServer.compose()
        .allowedDestinations("203.0.113.0/24,2001:db8::/32")
        .blockedDestinations("127.0.0.0/8,::1/128")
        .maxRelays(1000)
        .relayIdleTimeoutMs(5 * 60 * 1000)
        .listener(new SocksListener().port(1080).bindWildcard())
        .server();

Blocked destinations are evaluated first; then, if allowed destinations are set, the destination must match an allow rule. maxRelays caps concurrent relay sessions (0 = unlimited). setRelayIdleTimeoutMs(long) sets the idle timeout of a relay in milliseconds; the allowed and blocked destinations are lists of CidrNetwork (CidrNetwork.parseList("10.0.0.0/8,192.168.0.0/16") reads a comma-separated list).

Common listener options

TLS and transport settings (secure, keystore-file, keystore-pass, need-client-auth, tls-version, dtls-version, cipher-suites, named-groups), timeouts (idle-timeout, read-timeout, connection-timeout), bind addresses (addresses), rate limiting (rate-limit, max-connections-per-ip, max-auth-failures, auth-lockout-time), CIDR access control (allowed-networks, blocked-networks), and max-net-in-size are inherited from Listener / TcpListener and behave like other TCP-based services. See TLS & DTLS, Security, and main documentation (UNIX domain sockets).

Custom authorization

Compose a SocksServerSessionProvider (or use sessionPerConnection with a Supplier) to mint a SocksSessionHandler per accepted connection. The handler implements both ConnectHandler and BindHandler, approving or rejecting individual requests via ConnectState and BindState (see org.bluezoo.gumdrop.socks.server). With no session provider, the default behaviour applies (accept after filtering and relay limits). 

SocksServer server = SocksServer.compose()
        .listener(new SocksListener().port(1080).bindWildcard())
        .sessionPerConnection(new Supplier<SocksSessionHandler>() {
            @Override
            public SocksSessionHandler get() {
                return new MySocksSessionHandler();
            }
        })
        .server();

private static final class MySocksSessionHandler implements SocksSessionHandler {

    @Override
    public void handleConnect(ConnectState state, SocksRequest request,
                              Endpoint clientEndpoint) {
        if (isBlocked(request.getAddress())) {
            state.deny(SocksConstants.SOCKS5_REPLY_NOT_ALLOWED);
        } else {
            state.allow();
        }
    }

    @Override
    public void handleBind(BindState state, SocksRequest request,
                           Endpoint clientEndpoint) {
        state.allow();
    }
}

Client API

Use SocksClientHandler as the outer handler when connecting with ClientEndpoint to the proxy; it performs the SOCKS handshake then delegates to your inner protocol handler (for example SMTP or HTTP client handlers). 

// Connect to smtp.example.com:587 via SOCKS proxy at proxy:1080
ClientEndpoint client = new ClientEndpoint(factory, "proxy", 1080);
client.connect(new SocksClientHandler(
    "smtp.example.com", 587,
    new SmtpClientProtocolHandler(callback)));

// With SOCKS5 username/password
SocksClientConfig config = new SocksClientConfig("user", "pass");
client.connect(new SocksClientHandler(
    "smtp.example.com", 587, config,
    new SmtpClientProtocolHandler(callback)));

SocksClientConfig exposes version (AUTO, SOCKS4, SOCKS5), username / password, and handshake-timeout-ms (default 30 s).

Telemetry

When a TelemetryConfig is attached to the listener, SocksServerMetrics records counters and histograms for connections, CONNECT/BIND/UDP ASSOCIATE requests, relays, bytes, authentication outcomes, and blocked destinations. See Telemetry for OTLP setup.
