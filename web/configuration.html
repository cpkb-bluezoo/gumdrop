Application Composition

← Back to Main Page

Gumdrop 3 applications are assembled in Java: an explicit Runtime, transport Listeners, and handler implementations. There is no gumdroprc XML configuration in 3.0 — composition is the only supported way to deploy and document servers and clients.

Full reference: docs/COMPOSITION.md (plan: GUMDROP-3-PLAN.md §C.3–C.5).

Composition model

  1. Create a Runtime (reactor loops, timers, executors).
  2. Build protocol servers with listeners (port, TLS, …) and a handler (application logic).
  3. Register servers on the runtime and call start().

Implement HttpRequestHandler (or protocol-specific staged handlers for SMTP, IMAP, etc.). Do not subclass HttpServer, ServletServer, or WebdavServer for application code — those interim types are replaced by handler composition.

HTTP server

Runtime rt = Runtime.start(RuntimeConfig.builder().build());

HttpServer server = HttpServer.builder()
    .listener(HttpListener.builder().port(8080).build())
    .handler(new MyRequestHandler())
    .build();

rt.addServer(server);
server.start(rt);

See HTTP for listeners (HTTP/1.1, HTTP/2, HTTP/3), TLS, and handler callbacks.

Servlet container

The servlet stack is a ServletRequestHandler on HttpServer, not a separate ServletServer service: 

Container container = Container.builder()
    .context(Context.builder().path("").root(Path.of("web")).build())
    .build();

HttpServer server = HttpServer.builder()
    .listener(HttpListener.builder().port(8080).build())
    .handler(new ServletRequestHandler(container))
    .build();

Contexts, realms, clustering, and worker pools are configured on the Container / handler builders. See Servlet — composition.

File server and WebDAV

Static files and WebDAV (RFC 4918) use WebDAVRequestHandler (WebDAV is a tradename — not Webdav): 

HttpServer server = HttpServer.builder()
    .listener(HttpListener.builder().port(8080).build())
    .handler(WebDAVRequestHandler.builder()
        .rootPath(Path.of("/var/www/html"))
        .welcomeFile("index.html")
        .allowWrite(false)
        .webdavEnabled(true)
        .build())
    .build();

See File Server & WebDAV — composition.

Runtime and lifecycle

Runtime replaces the Gumdrop 2.x process singleton. Mail, FTP, DNS, and other protocols follow the same pattern: build a *Server (or client), register on the runtime, start. Complex stacks (mailbox + local delivery + SMTP) are wired in one Java main method.

Gumdrop 2.x XML (removed)

Gumdrop 2.x used gumdroprc XML with reflective dependency injection (ComponentRegistry, <service>, <property>, <ref>). That path is not supported in Gumdrop 3.0. Examples under etc/gumdroprc.* remain only for transitional regression tests, not for new deployments.

A future declarative configuration format is not planned until there is a concrete design. Do not maintain XML in parallel while the composition API is still evolving.
