Gumdrop AMQP Client

← Back to Main Page

Gumdrop provides a fully asynchronous AMQP 0-9-1 client for publishing and consuming messages against a broker such as RabbitMQ. Like all Gumdrop clients, the AMQP client uses non-blocking I/O and callbacks, and integrates directly with the framework's SelectorLoop event-driven architecture rather than pulling in a separate client thread model.

Architecture

The AMQP client follows the same patterns as other Gumdrop clients (Redis, LDAP, SMTP). It uses AMQP 0-9-1 framing for wire-level communication, with a streaming, no-copy frame parser (AMQPFrameParser) modeled on Gumdrop's HTTP/2 frame parser, so it never assumes a full frame or message body has arrived in a single read.

Key Components

  • org.bluezoo.gumdrop.amqp.client.AMQPClientRecovery - the recommended entry point: wraps a connection with automatic reconnection and topology/consumer replay
  • org.bluezoo.gumdrop.amqp.client.AMQPClientProtocolHandler - low-level endpoint handler implementing the AMQP 0-9-1 protocol for a single connection (no auto-reconnect)
  • org.bluezoo.gumdrop.amqp.client.handler.ClientConnection - interface for opening channels and closing the connection
  • org.bluezoo.gumdrop.amqp.client.handler.ClientChannel - interface exposing exchange/queue declaration, binding, publish, consume, ack/nack/reject, transactions, flow control, and publisher confirms
  • org.bluezoo.gumdrop.amqp.client.handler.RecoveryHandler - entry point callback fired once, on the first successful connection
  • org.bluezoo.gumdrop.amqp.client.handler.RecoveryListener - optional callback for connection-lost/reconnecting/recovered lifecycle events
  • Codec classes (AMQPFrame, AMQPMethod, FieldTable, BasicProperties, and per-class method codecs such as ExchangeMethods, QueueMethods, BasicMethods) - AMQP 0-9-1 wire encoding/decoding

The client targets publish/consume workloads rather than broker administration: exchange.delete, queue.unbind, queue.purge, and queue.delete are deliberately not exposed. Exchange types (direct, fanout, topic, headers, or broker plugin types), queue declaration, and routing-key bindings to exchanges (including the default exchange "", which routes by queue name) are fully supported.

Asynchronous Model

All AMQP operations are asynchronous. When you call an operation such as queueDeclare or basicPublish, it immediately encodes and sends the corresponding method frame, then returns. When the broker's reply arrives, your callback is invoked on the connection's SelectorLoop thread.

Basic Usage

Connect to a broker and declare a queue, then start consuming from it, using AMQPClientRecovery: 

AMQPClientRecovery client = new AMQPClientRecovery("broker.example.com", 5672)
        .credentials("guest", "guest")
        .virtualHost("/")
        .recoveryListener(myListener); // optional

client.connect(new RecoveryHandler() {
    public void onFirstConnect(ClientConnection connection) {
        connection.channelOpen(1, new ServerChannelOpenHandler() {
            public void handleChannelOpenOk(ClientChannel channel) {
                channel.queueDeclare("my-queue", true, false, false, null,
                        new ServerQueueDeclareHandler() {
                            public void handleQueueDeclareOk(
                                    String queue, long msgCount, long consumerCount) { }
                        });
                channel.basicConsume("my-queue", "", false, false, null,
                        myDeliveryHandler, new ServerConsumeHandler() {
                            public void handleConsumeOk(String consumerTag) { }
                        });
            }
        });
    }
});

AMQPClientRecovery hides the full connection handshake (protocol header, connection.start/start-ok, tune/tune-ok, open/open-ok) behind the stored host, port, credentials, virtual host, and TLS configuration. onFirstConnect fires exactly once, only for the initial successful connection - subsequent reconnects go straight to replay (see Automatic Connection Recovery).

SelectorLoop Affinity

Like other Gumdrop clients, AMQPClientRecovery can be pinned to a specific worker SelectorLoop so that connection I/O runs on the same event-loop thread as the code driving it: 

SelectorLoop loop = ((Request) req).getEndpoint().getSelectorLoop();
AMQPClientRecovery client = new AMQPClientRecovery(loop, "broker.example.com", 5672)
        .credentials("guest", "guest");

If no SelectorLoop is supplied, the client uses Gumdrop's default/shared loop. One deliberate deviation from the affinity model: the reconnect backoff timer itself does not run on a SelectorLoop timer, because idle worker loops (and their pending timers) can be torn down once there are no active clients, services, or listeners - which is exactly the state of a bare reconnecting client during a backoff window. Instead, reconnect delays run on a small dedicated daemon thread (gumdrop-amqp-recovery); the actual reconnect attempt itself still goes through the normal ClientEndpoint.connect path on the configured SelectorLoop.

Supported Operations

Operations exposed on ClientConnection:

  • channelOpen(channelId, ServerChannelOpenHandler)
  • close(replyCode, replyText, ServerCloseHandler)

Operations exposed on ClientChannel:

  • close(...) → ServerChannelCloseHandler
  • exchangeDeclare(...) → ServerExchangeDeclareHandler
  • queueDeclare(...) → ServerQueueDeclareHandler
  • queueBind(...) → ServerQueueBindHandler
  • basicPublish(exchange, routingKey, mandatory, properties, bodySize) - returns a streaming PublishBody writer
  • basicConsume(queue, consumerTag, noAck, exclusive, arguments, DeliveryHandler, ServerConsumeHandler)
  • basicCancel(consumerTag, ServerCancelHandler)
  • basicAck(deliveryTag, multiple), basicNack(deliveryTag, multiple, requeue) (RabbitMQ extension), basicReject(deliveryTag, requeue)
  • txSelect / txCommit / txRollback → ServerTxSelectHandler / ServerTxCommitHandler / ServerTxRollbackHandler
  • setFlowListener(FlowListener) (broker-initiated channel.flow, always auto-acknowledged) and flow(active, ServerFlowHandler) (client-initiated)
  • confirmSelect(ServerConfirmSelectHandler) (RabbitMQ extension) and setConfirmListener(ConfirmListener)

Publishing

basicPublish returns a streaming body writer, so message bodies are sent as a sequence of chunked frames rather than materialized as a single buffer - useful for large payloads: 

PublishBody body = channel.basicPublish("my-exchange", "routing.key",
        false, properties, payload.length);
body.write(ByteBuffer.wrap(payload));
body.finish();

The returned PublishBody also exposes getSequenceNumber(), which correlates the publish with the delivery tag reported by a subsequent publisher confirm (see Transactions & Confirms).

Consuming

Register a DeliveryHandler with basicConsume to receive messages for the lifetime of the consumer. Deliveries stream to the handler as they arrive; call basicAck, basicNack, or basicReject from within the handler once a message has been processed (unless the consumer was declared with noAck): 

channel.basicConsume("my-queue", "", false, false, null,
        new DeliveryHandler() {
            @Override
            public void handleDelivery(String consumerTag, long deliveryTag,
                    boolean redelivered, String exchange, String routingKey,
                    BasicProperties properties, byte[] body) {
                try {
                    process(body);
                    channel.basicAck(deliveryTag, false);
                } catch (Exception e) {
                    channel.basicNack(deliveryTag, false, true);
                }
            }
        },
        new ServerConsumeHandler() {
            @Override
            public void handleConsumeOk(String consumerTag) { }
        });

Transactions & Confirms

The channel supports both classic AMQP transactions (txSelect/txCommit/txRollback) and RabbitMQ's lighter-weight publisher confirms (confirmSelect + setConfirmListener), which acknowledge published messages individually rather than requiring a full transaction round-trip: 

channel.confirmSelect(new ServerConfirmSelectHandler() {
    @Override
    public void handleConfirmSelectOk() {
        channel.setConfirmListener(new ConfirmListener() {
            @Override
            public void handleAck(long deliveryTag, boolean multiple) {
                // message(s) up to deliveryTag confirmed by the broker
            }

            @Override
            public void handleNack(long deliveryTag, boolean multiple) {
                // message(s) up to deliveryTag rejected by the broker
            }
        });
    }
});

TLS Connections

The client supports implicit TLS (AMQPS, typically port 5671), configured on AMQPClientRecovery before connecting: 

AMQPClientRecovery client = new AMQPClientRecovery("broker.example.com", 5671)
        .credentials("guest", "guest")
        .setSecure(true)
        .setKeystoreFile("/path/to/keystore.p12")
        .setKeystorePass("changeit")
        .setKeystoreFormat("PKCS12");

A custom SSLContext or TrustManager may be supplied instead via setSSLContext / setTrustManager for full control over certificate validation. There is no STARTTLS-equivalent negotiation; TLS is established at connect time.

Authentication

The client authenticates using SASL PLAIN, the only mechanism currently implemented, sent as part of the connection.start-ok handshake once credentials are supplied via credentials(username, password).

Automatic Connection Recovery

AMQPClientRecovery automatically reconnects when the connection is lost - whether from a broker-initiated close, a transport error, or an IOException at connect time:

  • Reconnect delays follow a configurable RecoveryPolicy: exponential backoff, 1 second initial delay by default, doubling each attempt, capped at 30 seconds, with unlimited attempts unless a maximum is set via withMaxAttempts
  • On a successful reconnect (not the first connect), every exchange, queue, and binding that had been declared is redeclared, and every consumer is re-registered in its original order, so ClientChannel references the application already holds become live again with no code changes required
  • An optional RecoveryListener surfaces lifecycle events: onConnectionLost(cause), onReconnecting(attempt, delay), onRecovered(), and onRecoveryFailed(cause)
  • close() stops further reconnect attempts and closes the current endpoint
AMQPClientRecovery client = new AMQPClientRecovery("broker.example.com", 5672)
        .credentials("guest", "guest")
        .recoveryPolicy(RecoveryPolicy.exponentialBackoff()
                .withInitialDelay(1000)
                .withMaxDelay(30000)
                .withMaxAttempts(-1)) // unlimited
        .recoveryListener(new RecoveryListener() {
            @Override
            public void onConnectionLost(Throwable cause) {
                LOGGER.warning("AMQP connection lost: " + cause);
            }

            @Override
            public void onReconnecting(int attempt, long delayMillis) {
                LOGGER.info("Reconnecting to broker, attempt " + attempt);
            }

            @Override
            public void onRecovered() {
                LOGGER.info("AMQP connection recovered");
            }

            @Override
            public void onRecoveryFailed(Throwable cause) {
                LOGGER.severe("AMQP recovery failed: " + cause);
            }
        });

Server Integration Examples

Publishing Events from a Servlet

public class OrderServlet extends HttpServlet {

    private final AMQPClientRecovery amqp;
    private volatile ClientChannel channel;

    public OrderServlet() {
        amqp = new AMQPClientRecovery("broker.example.com", 5672)
                .credentials("app", "secret")
                .virtualHost("/orders");
        amqp.connect(new RecoveryHandler() {
            @Override
            public void onFirstConnect(ClientConnection connection) {
                connection.channelOpen(1, new ServerChannelOpenHandler() {
                    @Override
                    public void handleChannelOpenOk(ClientChannel ch) {
                        channel = ch;
                        channel.exchangeDeclare("orders", "topic", true, false,
                                false, null, new ServerExchangeDeclareHandler() {
                                    @Override
                                    public void handleExchangeDeclareOk() { }
                                });
                    }
                });
            }
        });
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        byte[] payload = toJson(req).getBytes(UTF_8);
        BasicProperties props = new BasicProperties.Builder()
                .contentType("application/json")
                .deliveryMode(2) // persistent
                .build();
        PublishBody body = channel.basicPublish("orders", "order.created",
                false, props, payload.length);
        body.write(ByteBuffer.wrap(payload));
        body.finish();
        resp.setStatus(202);
    }
}

Worker Queue Consumer with Confirms

public class OrderWorker {

    public void start() {
        AMQPClientRecovery amqp = new AMQPClientRecovery("broker.example.com", 5672)
                .credentials("worker", "secret")
                .virtualHost("/orders");

        amqp.connect(new RecoveryHandler() {
            @Override
            public void onFirstConnect(ClientConnection connection) {
                connection.channelOpen(1, new ServerChannelOpenHandler() {
                    @Override
                    public void handleChannelOpenOk(ClientChannel channel) {
                        channel.queueDeclare("order-processing", true, false,
                                false, null, new ServerQueueDeclareHandler() {
                                    @Override
                                    public void handleQueueDeclareOk(
                                            String queue, long msgCount, long consumerCount) {
                                        channel.queueBind("order-processing", "orders",
                                                "order.created", null,
                                                new ServerQueueBindHandler() {
                                                    @Override
                                                    public void handleQueueBindOk() {
                                                        consume(channel);
                                                    }
                                                });
                                    }
                                });
                    }
                });
            }
        });
    }

    private void consume(ClientChannel channel) {
        channel.basicConsume("order-processing", "", false, false, null,
                new DeliveryHandler() {
                    @Override
                    public void handleDelivery(String consumerTag, long deliveryTag,
                            boolean redelivered, String exchange, String routingKey,
                            BasicProperties properties, byte[] body) {
                        try {
                            processOrder(body);
                            channel.basicAck(deliveryTag, false);
                        } catch (Exception e) {
                            channel.basicNack(deliveryTag, false, true);
                        }
                    }
                },
                new ServerConsumeHandler() {
                    @Override
                    public void handleConsumeOk(String consumerTag) { }
                });
    }
}
