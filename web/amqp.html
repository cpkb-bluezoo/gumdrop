Gumdrop AMQP 0-9-1 Client

← Back to Main Page

This page describes the AMQP 0-9-1 client. AMQP 1.0 is a different protocol; Gumdrop has a separate AMQP 1.0 client in org.bluezoo.gumdrop.amqp1.client. The two share only the four-octet AMQP protocol header prefix. Use the 1.0 client for brokers that speak only AMQP 1.0, such as ActiveMQ Artemis's amqp:// acceptor, or RabbitMQ 4's native AMQP 1.0 listener.

Gumdrop provides a fully asynchronous AMQP 0-9-1 client for publishing and consuming messages against a broker such as RabbitMQ. Like all Gumdrop clients, the AMQP client uses non-blocking I/O and callbacks, and integrates directly with the framework's SelectorLoop event-driven architecture rather than pulling in a separate client thread model.

Architecture

The AMQP client follows the same patterns as other Gumdrop clients (Redis, LDAP, SMTP). It uses AMQP 0-9-1 framing for wire-level communication, with a streaming, no-copy frame parser (AmqpFrameParser) modelled on Gumdrop's HTTP/2 frame parser, so it never assumes a full frame or message body has arrived in a single read.

Key components

The client classes are in org.bluezoo.gumdrop.amqp.client; the wire codec is in org.bluezoo.gumdrop.amqp.

  • AmqpClient - the recommended entry point: wraps a connection with automatic reconnection and topology/consumer replay
  • AmqpClientProtocolHandler - low-level endpoint handler implementing the AMQP 0-9-1 protocol for a single connection (no auto-reconnect)
  • ClientConnection - interface for opening channels and closing the connection
  • ClientChannel - interface exposing exchange/queue declaration, binding, publish, consume, ack/nack/reject, transactions, flow control, and publisher confirms
  • RecoveryHandler - entry point callback fired once, on the first successful connection
  • RecoveryListener - optional callback for connection-lost, reconnecting and recovered lifecycle events
  • ClientHandshake - sends credentials via start-ok, either as a PLAIN username/password convenience or as an arbitrary SaslClientMechanism (AMQPLAIN, EXTERNAL, GSSAPI)
  • Codec classes (AmqpFrame, AmqpMethod, FieldTable, BasicProperties, and per-class method codecs such as ExchangeMethods, QueueMethods, BasicMethods) - AMQP 0-9-1 wire encoding/decoding

The client targets publish/consume workloads rather than broker administration: exchange.delete, queue.unbind, queue.purge, and queue.delete are deliberately not exposed. Exchange types (direct, fanout, topic, headers, or broker plugin types), queue declaration, and routing-key bindings to exchanges (including the default exchange "", which routes by queue name) are fully supported.

Asynchronous model

All AMQP operations are asynchronous. When you call an operation such as queueDeclare or basicPublish, it immediately encodes and sends the corresponding method frame, then returns. When the broker's reply arrives, your callback is invoked on the connection's SelectorLoop thread.

Basic usage

Connect to a broker and declare a queue, then start consuming from it, using AmqpClient:

In the client examples on this page, gumdrop is the Gumdrop instance returned by Gumdrop.boot(); a client is given it when it connects. 

AmqpClient client = new AmqpClient("broker.example.com", 5672)
        .credentials("guest", "guest")
        .virtualHost("/")
        .recoveryListener(myListener); // optional

client.connect(gumdrop, new RecoveryHandler() {
    public void onFirstConnect(ClientConnection connection) {
        connection.channelOpen(1, new ChannelOpenHandler() {
            public void handleChannelOpenOk(ClientChannel channel) {
                channel.queueDeclare("my-queue", true, false, false, null,
                        new QueueDeclareHandler() {
                            public void handleQueueDeclareOk(
                                    String queue, long msgCount, long consumerCount) { }
                        });
                channel.basicConsume("my-queue", "", false, false, null,
                        myDeliveryHandler, new ConsumeHandler() {
                            public void handleConsumeOk(String consumerTag) { }
                        });
            }
        });
    }
});

AmqpClient hides the full connection handshake (protocol header, connection.start/start-ok, tune/tune-ok, open/open-ok) behind the stored host, port, credentials, virtual host, and TLS configuration. onFirstConnect fires exactly once, only for the initial successful connection - subsequent reconnects go straight to replay (see Automatic connection recovery).

SelectorLoop affinity

Like other Gumdrop clients, AmqpClient can be pinned to a specific worker SelectorLoop so that connection I/O runs on the same event-loop thread as the code driving it: 

SelectorLoop loop = gumdrop.nextWorkerLoop();
AmqpClient client = new AmqpClient(loop, "broker.example.com", 5672)
        .credentials("guest", "guest");

If no SelectorLoop is supplied, the client uses Gumdrop's default/shared loop. One deliberate deviation from the affinity model: the reconnect backoff timer itself does not run on a SelectorLoop timer, because idle worker loops (and their pending timers) can be torn down once there are no active clients, services, or listeners - which is exactly the state of a bare reconnecting client during a backoff window. Instead, reconnect delays run on a small dedicated daemon thread (gumdrop-amqp-recovery); the actual reconnect attempt itself still goes through the normal ClientEndpoint.connect path on the configured SelectorLoop.

Supported operations

Operations exposed on ClientConnection:

  • channelOpen(channelId, ChannelOpenHandler)
  • close(replyCode, replyText, CloseHandler)

Operations exposed on ClientChannel:

  • close(...) → ChannelCloseHandler
  • exchangeDeclare(...) → ExchangeDeclareHandler
  • queueDeclare(...) → QueueDeclareHandler
  • queueBind(...) → QueueBindHandler
  • basicPublish(exchange, routingKey, mandatory, properties, bodySize) - returns a streaming PublishBody writer
  • basicConsume(queue, consumerTag, noAck, exclusive, arguments, DeliveryHandler, ConsumeHandler)
  • basicCancel(consumerTag, CancelHandler)
  • basicAck(deliveryTag, multiple), basicNack(deliveryTag, multiple, requeue) (RabbitMQ extension), basicReject(deliveryTag, requeue)
  • txSelect / txCommit / txRollback → TxSelectHandler / TxCommitHandler / TxRollbackHandler
  • setFlowListener(FlowListener) (broker-initiated channel.flow, always auto-acknowledged) and flow(active, FlowHandler) (client-initiated)
  • confirmSelect(ConfirmSelectHandler) (RabbitMQ extension) and setConfirmListener(ConfirmListener)

Publishing

basicPublish returns a streaming body writer, so message bodies are sent as a sequence of chunked frames rather than materialised as a single buffer - useful for large payloads: 

PublishBody body = channel.basicPublish("my-exchange", "routing.key",
        false, properties, payload.length);
body.writeBody(ByteBuffer.wrap(payload));
body.complete();

The total written across all writeBody calls must equal the bodySize given to basicPublish, and onWriteReady(Runnable) tells a writer of a large body when the transport can take more. The returned PublishBody also exposes getSequenceNumber(), which correlates the publish with the sequence number reported by a subsequent publisher confirm (see Transactions & confirms).

Consuming

Register a DeliveryHandler with basicConsume to receive messages for the lifetime of the consumer. A message is delivered in four calls, in order: onDeliveryStart, onDeliveryProperties, onDeliveryBodyChunk (zero or more times, as body frames arrive; the buffer is only valid during the call) and onDeliveryComplete. The body is never buffered whole by the client, so a handler that needs all of it collects the chunks. Acknowledge with basicAck, basicNack or basicReject only after onDeliveryComplete (unless the consumer was declared with noAck): 

channel.basicConsume("my-queue", "", false, false, null,
        new DeliveryHandler() {
            private long deliveryTag;
            private final ByteArrayOutputStream body = new ByteArrayOutputStream();

            public void onDeliveryStart(String consumerTag, long deliveryTag,
                    boolean redelivered, String exchange, String routingKey) {
                this.deliveryTag = deliveryTag;
                body.reset();
            }

            public void onDeliveryProperties(BasicProperties properties, long bodySize) { }

            public void onDeliveryBodyChunk(ByteBuffer chunk) {
                byte[] copy = new byte[chunk.remaining()];
                chunk.get(copy);
                body.write(copy, 0, copy.length);
            }

            public void onDeliveryComplete() {
                try {
                    process(body.toByteArray());
                    channel.basicAck(deliveryTag, false);
                } catch (Exception e) {
                    channel.basicNack(deliveryTag, false, true);
                }
            }
        },
        new ConsumeHandler() {
            public void handleConsumeOk(String consumerTag) { }
        });

Transactions & confirms

The channel supports both classic AMQP transactions (txSelect/txCommit/txRollback) and RabbitMQ's lighter-weight publisher confirms (confirmSelect + setConfirmListener), which acknowledge published messages individually rather than requiring a full transaction round-trip: 

channel.confirmSelect(new ConfirmSelectHandler() {
    @Override
    public void handleConfirmSelectOk() {
        channel.setConfirmListener(new ConfirmListener() {
            @Override
            public void onAck(long sequenceNumber, boolean multiple) {
                // publish(es) up to sequenceNumber confirmed by the broker
            }

            @Override
            public void onNack(long sequenceNumber, boolean multiple) {
                // publish(es) up to sequenceNumber rejected by the broker
            }
        });
    }
});

TLS connections

The client supports implicit TLS (AMQPS, typically port 5671), configured on AmqpClient before connecting: 

AmqpClient client = new AmqpClient("broker.example.com", 5671)
        .credentials("guest", "guest")
        .secure(true)
        .tls(TlsConfig.keystore(Path.of("/path/to/keystore.p12"), "changeit",
                KeystoreFormat.PKCS12));

A custom X509TrustManager may be supplied on the TlsConfig (trustManager()) for full control over certificate validation. There is no STARTTLS-equivalent negotiation; TLS is established at connect time.

Authentication

The client supports SASL PLAIN (the default), AMQPLAIN (RabbitMQ's field-table-encoded credentials), EXTERNAL (TLS client certificate), and GSSAPI (Kerberos). Select a mechanism with mechanism(...); the broker's advertised mechanism list is validated against the request before authenticating, so an unsupported choice fails clearly rather than silently falling back to PLAIN: 

AmqpClient client = new AmqpClient("broker.example.com", 5672)
        .credentials("appuser", "s3cret")
        .mechanism("AMQPLAIN");

EXTERNAL relies on the client certificate presented during the TLS handshake (see TLS connections) and ignores credentials: 

AmqpClient client = new AmqpClient("broker.example.com", 5671)
        .secure(true)
        .tls(TlsConfig.keystore(Path.of("/path/to/client-cert.p12"), "changeit"))
        .mechanism("EXTERNAL");

GSSAPI requires a JAAS Subject obtained from a keytab login (or kinit), the broker's service principal name, and a worker executor — the first challenge evaluation may block on KDC contact, so it must never run on the connection's own event-loop thread: 

Subject subject = loginWithKeytab("amqp-client@EXAMPLE.COM", "/etc/keytabs/amqp-client.keytab");
ExecutorService kerberosExecutor = Executors.newSingleThreadExecutor();

AmqpClient client = new AmqpClient("broker.example.com", 5672)
        .mechanism("GSSAPI")
        .gssapiCredentials(subject, "amqp@broker.example.com", kerberosExecutor);

For lower-level control (or mechanisms this convenience API doesn't cover), ClientHandshake accepts any SaslClientMechanism directly — see org.bluezoo.gumdrop.auth.SaslUtils#createClient — via startOk(SaslClientMechanism, TuneHandler) or, for blocking mechanisms, startOk(SaslClientMechanism, TuneHandler, ExecutorService). Multi-step mechanisms are handled transparently: the client responds to as many connection.secure challenges as the broker sends before connection.tune.

Automatic connection recovery

AmqpClient automatically reconnects when the connection is lost - whether from a broker-initiated close, a transport error, or an IOException at connect time:

  • Reconnect delays follow a configurable RecoveryPolicy: exponential backoff, 1 second initial delay by default, doubling each attempt (withMultiplier), capped at 30 seconds, with unlimited attempts (0) unless a maximum number of consecutive failed attempts is set via withMaxAttempts; the other settings are withInitialDelayMs and withMaxDelayMs
  • On a successful reconnect (not the first connect), every exchange, queue, and binding that had been declared is redeclared, and every consumer is re-registered in its original order, so ClientChannel references the application already holds become live again with no code changes required
  • An optional RecoveryListener (all its methods are defaults, so implement only those you want) surfaces lifecycle events: onConnectionLost(cause), onReconnecting(attempt, delayMs), onRecovered(), and onRecoveryFailed(cause)
  • close() stops further reconnect attempts and closes the current endpoint
AmqpClient client = new AmqpClient("broker.example.com", 5672)
        .credentials("guest", "guest")
        .recoveryPolicy(new RecoveryPolicy()
                .withInitialDelayMs(1000)
                .withMaxDelayMs(30000)
                .withMultiplier(2.0)
                .withMaxAttempts(0)) // 0 = unlimited
        .recoveryListener(new RecoveryListener() {
            @Override
            public void onConnectionLost(Exception cause) {
                LOGGER.warning("AMQP connection lost: " + cause);
            }

            @Override
            public void onReconnecting(int attempt, long delayMs) {
                LOGGER.info("Reconnecting to broker, attempt " + attempt);
            }

            @Override
            public void onRecovered() {
                LOGGER.info("AMQP connection recovered");
            }

            @Override
            public void onRecoveryFailed(Exception cause) {
                LOGGER.severe("AMQP recovery failed: " + cause);
            }
        });

Server integration examples

Publishing events from a servlet

public class OrderServlet extends HttpServlet {

    private final AmqpClient amqp;
    private volatile ClientChannel channel;

    public OrderServlet() {
        amqp = new AmqpClient("broker.example.com", 5672)
                .credentials("app", "secret")
                .virtualHost("/orders");
        amqp.connect(gumdrop, new RecoveryHandler() {
            @Override
            public void onFirstConnect(ClientConnection connection) {
                connection.channelOpen(1, new ChannelOpenHandler() {
                    @Override
                    public void handleChannelOpenOk(ClientChannel ch) {
                        channel = ch;
                        channel.exchangeDeclare("orders", "topic", true, false,
                                null, new ExchangeDeclareHandler() {
                                    @Override
                                    public void handleExchangeDeclareOk() { }
                                });
                    }
                });
            }
        });
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        byte[] payload = toJson(req).getBytes(UTF_8);
        BasicProperties props = new BasicProperties()
                .withContentType("application/json")
                .withDeliveryMode((byte) 2); // persistent
        PublishBody body = channel.basicPublish("orders", "order.created",
                false, props, payload.length);
        body.writeBody(ByteBuffer.wrap(payload));
        body.complete();
        resp.setStatus(202);
    }
}

Worker queue consumer

public class OrderWorker {

    public void start() {
        AmqpClient amqp = new AmqpClient("broker.example.com", 5672)
                .credentials("worker", "secret")
                .virtualHost("/orders");

        amqp.connect(gumdrop, new RecoveryHandler() {
            @Override
            public void onFirstConnect(ClientConnection connection) {
                connection.channelOpen(1, new ChannelOpenHandler() {
                    @Override
                    public void handleChannelOpenOk(ClientChannel channel) {
                        channel.queueDeclare("order-processing", true, false,
                                false, null, new QueueDeclareHandler() {
                                    @Override
                                    public void handleQueueDeclareOk(
                                            String queue, long msgCount, long consumerCount) {
                                        channel.queueBind("order-processing", "orders",
                                                "order.created", null,
                                                new QueueBindHandler() {
                                                    @Override
                                                    public void handleQueueBindOk() {
                                                        consume(channel);
                                                    }
                                                });
                                    }
                                });
                    }
                });
            }
        });
    }

    private void consume(final ClientChannel channel) {
        channel.basicConsume("order-processing", "", false, false, null,
                new DeliveryHandler() {
                    private long deliveryTag;
                    private final ByteArrayOutputStream body = new ByteArrayOutputStream();

                    @Override
                    public void onDeliveryStart(String consumerTag, long deliveryTag,
                            boolean redelivered, String exchange, String routingKey) {
                        this.deliveryTag = deliveryTag;
                        body.reset();
                    }

                    @Override
                    public void onDeliveryProperties(BasicProperties properties,
                            long bodySize) { }

                    @Override
                    public void onDeliveryBodyChunk(ByteBuffer chunk) {
                        byte[] copy = new byte[chunk.remaining()];
                        chunk.get(copy);
                        body.write(copy, 0, copy.length);
                    }

                    @Override
                    public void onDeliveryComplete() {
                        try {
                            processOrder(body.toByteArray());
                            channel.basicAck(deliveryTag, false);
                        } catch (Exception e) {
                            channel.basicNack(deliveryTag, false, true);
                        }
                    }
                },
                new ConsumeHandler() {
                    @Override
                    public void handleConsumeOk(String consumerTag) { }
                });
    }
}
